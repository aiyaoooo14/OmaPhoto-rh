| `.github/workflows/release-rh.yml` | matrix `[10, 9]` 双包发布,SHA256SUMS 双条目 |

README 修了一处**两边共有**的陈旧文案:"EL9 暂未适配"(家中的翻译提交早于 el9 实装,漏更新)。
教训:**git 行级自动合并会放过语义陈旧**——两边都写了同一句过时话时,零冲突不等于正确。

## 核心教训(重要,下次别再犯)

1. **两真机各自全测 + 合并零源码变化 ⇒ 合并后不必重测。** 本次我在本机重跑了 build-rh
   增量 + ctest,结果是:ninja 中断在 251/1522,ctest 跑新旧混合产物,12 个"失败"全是
   环境噪音,还干扰了正在使用的 GUI 实例。**build-rh 是工作现场,别人(包括 AI)不许动。**
2. **30km 约束**:两台真机无法现场往返,一切动作单机完成、移动盘传 bundle、GitHub 做最终源。
   提出的任何"去另一台机器验证"的方案都是废话。
3. **https push 在无终端环境会卡 askpass**。永久改 SSH remote:
   `git remote set-url origin git@github.com:aiyaoooo14/OmaPhoto-rh.git`
